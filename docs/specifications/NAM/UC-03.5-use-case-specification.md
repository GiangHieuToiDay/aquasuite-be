# UC-03.5 – Manage Role Permissions

> English version of `UC-03.5-use-case-specification.vi.md` (the Vietnamese version is the source; keep both in sync). Written to match the **current code**. Messages are quoted exactly as they appear on the screen (Vietnamese).
> The former name "Create Custom Role" is no longer correct: the system has only **5 fixed roles** and the Shop Owner can only **assign or unassign permissions** of those roles.

|  |  |  |  |
| :-: | :-- | :-: | :-- |
| Primary Actors | Shop Owner | Secondary Actors | None |
| Created By | Pham Van Nam | Created Date | 24/11/2026 |
| Description | As the Shop Owner, I want to view the 5 fixed roles of the system and the permissions currently assigned to each role, and to assign or unassign permissions of a role, so that I can adjust the functions that each user group is allowed to use. |  |  |
| Preconditions | 1. The user is logged in with the Shop Owner role.<br>2. The system has all 5 fixed roles and the permission catalog. |  |  |
| Normal Flow | **Assign a permission to a role**<br>1. The Shop Owner opens the Role Management page.<br>2. The system displays the list of the 5 fixed roles in a fixed order: Shop Owner, Sales Staff, Accountant, Shipper, Customer (GBR-AC-01).<br>3. The Shop Owner selects a role.<br>4. The system displays the "Quyền của vai trò" (Role permissions) section with the permissions already assigned to the role and the list of permissions in the system, each with a code and a description.<br>5. The Shop Owner chooses "Gán quyền" (Assign) on a permission that is not assigned yet.<br>6. The system displays the "Xác nhận gán quyền" (Confirm assignment) dialog showing the role, the permission and the note "Thay đổi có thể ảnh hưởng mọi tài khoản mang vai trò này, kể cả bạn."<br>7. The Shop Owner chooses "Xác nhận gán quyền".<br>8. The system checks that the role and the permission still exist and assigns the permission to the role.<br>9. The system refreshes the role permissions section and displays “Đã gán quyền cho vai trò.”. From now on the permission is effective for all accounts that have this role (GBR-AC-03). |  |  |
| Alternative Flows | **Step 5_Unassign a permission from a role**<br>1. The Shop Owner chooses "Gỡ quyền" (Unassign) on a permission already assigned to the role.<br>2. The system displays the "Xác nhận gỡ quyền" dialog with the same note as in step 6.<br>3. The Shop Owner chooses "Xác nhận gỡ quyền".<br>4. The system removes the permission from the role, refreshes the role permissions section and displays “Đã gỡ quyền khỏi vai trò.”. The use case ends.<br><br>**Step 4_Search permissions**<br>1. The Shop Owner types a keyword in the "Tìm theo mã hoặc mô tả" field.<br>2. The system shows only the permissions whose code or description matches the keyword. If no permission matches, the system displays “Không tìm thấy quyền.”<br>3. Return to step 5.<br><br>**Step 7_Cancel**<br>1. The Shop Owner chooses "Hủy" (Cancel) on the confirmation dialog.<br>2. The system closes the dialog and does not change the role permissions. The use case ends.<br><br>**Step 8_Permission already assigned / not assigned**<br>1. If the permission is already assigned to the role (when assigning), or is not assigned (when unassigning) because another action has just done it, the system does not create a duplicate record and does not change any data.<br>2. The system shows the result like a successful action, with the latest permission list. |  |  |
| Exception Flow | **Step 1_No access**<br>1. If the user is not signed in or the session has expired, the system displays “Chưa xác thực hoặc phiên đăng nhập đã hết hạn”.<br>2. If the user is not the Shop Owner (GBR-AC-02), the system displays “Bạn không có quyền thực hiện thao tác này”.<br>3. The system does not display any role data. The use case ends.<br><br>**Step 2_Roles cannot be loaded**<br>1. If the system cannot load the role list, it displays “Không tải được vai trò.” with a retry button.<br>2. The Shop Owner chooses retry. Return to step 1.<br><br>**Step 4_Role details cannot be loaded**<br>1. If the system cannot load the details of the selected role, it displays “Không tải được chi tiết vai trò.” with a retry button.<br>2. The Shop Owner chooses retry. Return to step 3.<br><br>**Step 8_Role or permission no longer exists**<br>1. If the role does not exist, the system displays “Không tìm thấy vai trò yêu cầu”.<br>2. If the permission does not exist (for example it was just deleted), the system displays “Không tìm thấy quyền yêu cầu”.<br>3. The system changes no data and reloads the list. Return to step 3.<br><br>**Step 8_Result not determined**<br>1. If the request is interrupted (connection lost, timeout or server error), the system displays “Chưa xác định kết quả. Hãy tải lại dữ liệu vai trò trước khi thao tác tiếp.”<br>2. The system temporarily locks the assign and unassign actions and displays “Dữ liệu vai trò cần được đối soát sau thao tác chưa xác định kết quả. Vui lòng tải lại dữ liệu từ máy chủ.”<br>3. The Shop Owner chooses reload; the system displays “Đã tải lại dữ liệu vai trò. Vui lòng kiểm tra trước khi tiếp tục.” and unlocks the actions. Return to step 3. |  |  |
| Postconditions | 1. After step 9 the permission is assigned to the role (or removed from the role in the "Unassign" flow); the change is effective immediately for all accounts that have this role.<br>2. When the action is not successful or is cancelled, the role permissions do not change.<br>3. The list of the 5 roles and the permission catalog are not changed by this use case. |  |  |

## Business Rules
| GBR-ID | Rule Statement | Applies To | Rationale | Enforced By |
| :-: | :-- | :-: | :-- | :-- |
| **GBR-AC-01** | The system has exactly 5 fixed roles: Shop Owner, Sales Staff, Accountant, Shipper, Customer. The system does not allow creating, renaming or deleting roles; roles are always shown in a fixed order. | UC-03.5 (step 2) | Keep the permission model simple, stable and aligned with the store's user groups. | System (role and permission service) and database (fixed roles cannot be renamed or deleted) |
| **GBR-AC-02** | Only the Shop Owner can view the roles and change the permissions of a role. | UC-03.5 (step 1) | Access rights are sensitive; only the store owner may decide them. | System (user role check) |
| **GBR-AC-03** | A change of role permissions takes effect on the next request of every account with that role, including the Shop Owner who made the change; users do not need to log in again. | UC-03.5 (step 9) | Permissions always reflect the latest configuration; no outdated permission stays in effect. | System (the user's permissions are determined from current data on every request) |

## Out of Scope (not supported by the current code or covered by another use case)

| Item | Note |
| :-- | :-- |
| Creating a new role, renaming or deleting a role | The system has only 5 fixed roles |
| Adding, editing or deleting permissions in the permission catalog | A separate permission catalog management use case |
| Logging changes of role permissions | Not logged yet (who, when, old and new values) |
| Assigning roles to user accounts | A separate account management use case |
