# UC-06.2 – Update/Delete Category

> English version of `UC-06.2-use-case-specification.vi.md` (the Vietnamese version is the source; keep both in sync). Written to match the **current code**. Messages are quoted exactly as they appear on the screen (Vietnamese).
> "Delete category" is a **soft delete**: the category changes to the Inactive status (hidden) and its data is kept. Viewing the list, viewing details and adding a category belong to UC-06.1.

|  |  |  |  |
| :-: | :-- | :-: | :-- |
| Primary Actors | Shop Owner (or a user who has been granted the category management permissions) | Secondary Actors | None |
| Created By | Pham Van Nam | Created Date | 24/11/2026 |
| Description | As the Shop Owner, I want to edit the information, change the parent category, hide or show again, and delete a category, so that the product category structure always matches the real business. |  |  |
| Preconditions | 1. The user is logged in.<br>2. The user has the permission to edit categories (and the permission to delete categories when deleting), granted to the user's role by the Shop Owner (UC-03.5).<br>3. The category to edit or delete exists and the user is viewing the category list (UC-06.1). |  |  |
| Normal Flow | **Update a category**<br>1. The user chooses "Sửa" (Edit) on a category in the list.<br>2. The system displays the "Sửa danh mục" form with the current data. The category code field cannot be edited (“Mã là khóa ổn định và không thể thay đổi.”) and the Parent category list does not contain the category being edited.<br>3. The user edits the name, description, parent category or status (Active, Inactive) and submits the form.<br>4. The system validates the entered data (Category data: the code is required, at most 50 characters, only letters A-Z, digits and underscores, the first character a letter or digit (lower case is converted to upper case); the name is required, at most 100 characters; the description is at most 5000 characters (empty means no description); leading and trailing spaces are removed; the status is Active or Inactive (default Active)).<br>5. The system checks that the name is not duplicated under the same parent according to GBR-CG-02 and checks the parent category according to GBR-CG-03.<br>6. The system saves the changes.<br>7. The system closes the form, refreshes the list and displays “Đã cập nhật danh mục.” |  |  |
| Alternative Flows | **Step 3_Hide or show a category again**<br>1. The user changes the Status to "Ngừng hoạt động" (Inactive) to hide the category, or to "Hoạt động" (Active) to show it again, and submits the form.<br>2. The system saves the new status. An Inactive category is hidden from the selection lists and from the store (GBR-CG-04); the status of its child categories is not changed (GBR-CG-06). Continue at step 7.<br><br>**Step 3_Change the parent category**<br>1. The user selects another parent category, or selects "Danh mục gốc" to move the category to the root level, and submits the form.<br>2. The system checks according to GBR-CG-03 and saves. All child categories of the category move together with it. Continue at step 4.<br><br>**Step 3_Cancel**<br>1. The user closes the form without submitting.<br>2. The system does not save any change. The use case ends.<br><br>**Step 1_Delete a category**<br>1. The user chooses "Xóa" (Delete) on a category.<br>2. The system displays the "Xác nhận xóa danh mục" dialog showing the category code and name.<br>3. The user chooses "Xóa danh mục".<br>4. The system checks that the category has no child category (GBR-CG-05), changes the category to the Inactive status and keeps its data.<br>5. The system closes the dialog, refreshes the list (the category is still shown with the status Ngừng hoạt động) and displays “Đã xóa danh mục.” The use case ends.<br><br>**Step 3_Cancel the deletion**<br>1. The user chooses "Hủy" on the delete confirmation dialog.<br>2. The system closes the dialog and does not change any data. The use case ends. |  |  |
| Exception Flow | **Step 1_No access**<br>1. If the user is not signed in or the session has expired, the system displays “Chưa xác thực hoặc phiên đăng nhập đã hết hạn”.<br>2. If the user does not have the permission, the system displays “Tài khoản không có quyền thực hiện thao tác này.”<br>3. The system does not change any data. The use case ends.<br><br>**Step 4_Invalid data**<br>1. If the data is invalid, the system does not send the data and displays an error next to the invalid field: “Vui lòng nhập tên.”, “Tên tối đa 100 ký tự.”, “Mô tả tối đa 5000 ký tự.”<br>2. The user corrects the data. Return to step 3.<br><br>**Step 5_Duplicate name**<br>1. If the name already exists under the same parent category (GBR-CG-02), the system does not save and displays “Tên danh mục đã tồn tại trong cùng danh mục cha.”<br>2. The user corrects the data. Return to step 3.<br><br>**Step 5_Invalid parent category**<br>1. If the selected parent is the category being edited, the system does not save and displays “Danh mục không thể là cha của chính nó.”<br>2. If the selected parent is a child or descendant of the category being edited, the system does not save and displays “Không thể chọn danh mục con làm cha vì sẽ tạo vòng lặp.”<br>3. If the parent category no longer exists, the system does not save and displays “Danh mục cha không còn tồn tại.”<br>4. If the category structure is in conflict, the system does not save and displays “Cấu trúc danh mục đang xung đột. Vui lòng tải lại và thử lại.”<br>5. The user selects the parent category again. Return to step 3.<br><br>**Step 3_Category no longer exists**<br>1. If the category to edit or delete no longer exists, the system changes no data and displays “Không tìm thấy danh mục yêu cầu”.<br>2. The user closes the dialog and reloads the list. Return to step 1.<br><br>**Step 4_Category with child categories cannot be deleted**<br>1. If the category has child categories, including inactive ones (GBR-CG-05), the system does not delete it and displays in the confirmation dialog “Không thể xóa danh mục đang có danh mục con.”<br>2. The user closes the dialog, or handles the child categories and deletes again. The use case ends. |  |  |
| Postconditions | 1. After step 7 the name, description, parent category and status of the category are updated; the category code does not change.<br>2. After the "Delete a category" flow the category is Inactive and is still in the data; because a category can be deleted only when it has no child category, the tree structure is not broken.<br>3. When the action is not successful or is cancelled, the category data does not change. |  |  |

## Business Rules
| GBR-ID | Rule Statement | Applies To | Rationale | Enforced By |
| :-: | :-- | :-: | :-- | :-- |
| **GBR-CG-01** | The category code is unique in the whole system (ignoring letter case) and cannot be changed after creation. | UC-06.1 (step 7), UC-06.2 (step 2) | The code is a stable key that other functions (products, Excel import) use to refer to a category. | System (category service) and database (unique key) |
| **GBR-CG-02** | A category name is unique under the same parent category; root categories cannot have the same name. | UC-06.1 (step 7), UC-06.2 (step 5) | Avoid confusion when choosing among categories on the same level. | System (category service) |
| **GBR-CG-03** | A category has at most one parent category, or is a root category. The parent category must exist; a category cannot be its own parent and cannot take its own child or descendant as its parent (no loops). The system does not limit the number of levels. | UC-06.1 (step 8), UC-06.2 (step 5) | Keep the tree valid and prevent loops that would break walking through the category tree. | System (category service) and database (parent foreign key) |
| **GBR-CG-04** | A category with the Inactive status is hidden from the category selection lists (choosing a parent category, choosing a category for a product), from the Excel product import and from the category list shown to customers in the store; it can still be seen in the Category Management page. | UC-06.1 (step 4), UC-06.2 (step 3) | Allow a category to stop being used without losing data and without affecting customers. | System (the category, store and Excel import services only use active categories) |
| **GBR-CG-05** | Deleting a category is a soft delete: the category changes to the Inactive status and its data is kept. A category that has child categories (even inactive ones) cannot be deleted. Deleting a category that is already Inactive causes no error and changes nothing. | UC-06.2 (step 4 of the "Delete a category" flow) | Keep the history and the product references, and do not orphan child categories. | System (category service) |
| **GBR-CG-06** | Changing a category to the Inactive status does not change the status of its child categories. | UC-06.2 (step 3_Hide or show a category again) | Allow hiding each category separately; the user decides whether to hide the whole branch. | System (category service) |

## Out of Scope (not supported by the current code or covered by another use case)

| Item | Note |
| :-- | :-- |
| Permanently deleting a category from the database | "Delete" always changes the category to Inactive |
| Automatically hiding child categories when a parent is hidden | The system does not change the status of child categories |
| Blocking deletion or hiding of a category that has products | The system does not check products on a soft delete |
| Changing a category code | The code cannot be changed after creation |
| Viewing the list, viewing details, adding a category | Covered by UC-06.1 |
