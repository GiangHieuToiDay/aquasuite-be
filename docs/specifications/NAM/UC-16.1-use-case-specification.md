# UC-16.1 – Create Goods Receipt from Purchase Order

> English version of `UC-16.1-use-case-specification.vi.md` (the Vietnamese version is the source; keep both in sync). Written to match the **current code**. Messages are quoted exactly as they appear on the screen (Vietnamese).
> In the system, **creating a goods receipt also confirms it**: stock is increased immediately when the receipt is created and the receipt cannot be edited or cancelled. There is no draft receipt.

|  |  |  |  |
| :-: | :-- | :-: | :-- |
| Primary Actors | Shop Owner, Accountant | Secondary Actors | None |
| Created By | Pham Van Nam | Created Date | 24/11/2026 |
| Description | As the Shop Owner or an Accountant, I want to create a goods receipt for the quantities actually received on a confirmed purchase order, so that stock is increased correctly, the purchase order tracks the received and remaining quantities, and the receiving is recorded with traceability. |  |  |
| Preconditions | 1. The user is logged in with the Shop Owner or Accountant role.<br>2. The purchase order exists, is in the "Đã xác nhận" (Confirmed) or "Nhận một phần" (Partially received) status and still has lines that are not fully received. |  |  |
| Normal Flow | **Create a goods receipt**<br>1. The user opens the details of the purchase order to receive.<br>2. The system displays the "Nhập kho" (Receive goods) button (only when the order is "Đã xác nhận" or "Nhận một phần" and the user has the permission).<br>3. The user chooses "Nhập kho".<br>4. The system displays the "Nhập kho theo đơn mua" dialog showing the order code and the receiving warehouse, the list of lines still to be received with Sản phẩm / SKU, ĐVT (unit), Còn lại (remaining), Thực nhận (received now, default equal to the remaining quantity) and Thành tiền (amount), the "Số hóa đơn NCC" (supplier invoice number) field, the "Ghi chú" (note) field, the "Tạm tính giá trị phiếu" (estimated receipt value) line and the notice “Khi xác nhận, tồn kho được cộng ngay và phiếu không thể sửa. Hãy kiểm tra kỹ số lượng thực nhận trước khi lập phiếu.”<br>5. The user adjusts the received quantity of each line (0 means the line is not received in this batch), enters the supplier invoice number and a note if any, and chooses "Lập & xác nhận phiếu" (Create and confirm receipt).<br>6. The system validates the entered data (A goods receipt must have at least one line with a received quantity greater than 0; the received quantity of a line cannot be negative or exceed the remaining quantity; each purchase order line appears only once in the same receipt; the supplier invoice number and the note are optional).<br>7. The system checks the duplicate-prevention code, checks that the purchase order may be received according to GBR-GR-01 and checks the received lines according to GBR-GR-02.<br>8. The system creates the goods receipt in the "Đã xác nhận" (Confirmed) status with a generated receipt code, the current date as the receipt date, and the creating and confirming user (GBR-GR-03).<br>9. The system increases the stock of each SKU in the purchase order's warehouse by the received quantity and records the stock history for each line (GBR-GR-03).<br>10. The system updates the received quantities of the purchase order lines and the purchase order status according to GBR-GR-04.<br>11. The system closes the dialog, refreshes the purchase order details and displays “Đã lập phiếu nhập kho <mã phiếu> cho đơn <mã đơn>” |  |  |
| Alternative Flows | **Step 5_Partial receipt**<br>1. The user enters a quantity smaller than the remaining quantity, or receives only some of the lines.<br>2. The system creates the receipt for the received part; the purchase order becomes "Nhận một phần" and the lines not fully received still have a remaining quantity (GBR-GR-04). The user creates another receipt at later deliveries.<br><br>**Step 7_Same request submitted again**<br>1. If the request is submitted again (several clicks, or a resend after a network error) with the same content, the system does not create another receipt and does not increase the stock again.<br>2. The system returns the receipt already created and displays the message as in step 11.<br><br>**Step 5_Cancel**<br>1. The user chooses "Hủy bỏ" or closes the dialog.<br>2. The system creates no receipt and does not change the stock. The use case ends. |  |  |
| Exception Flow | **Step 2_No permission**<br>1. If the user is not signed in or the session has expired, the system displays “Chưa xác thực hoặc phiên đăng nhập đã hết hạn”.<br>2. If the user is not a Shop Owner or an Accountant, the system does not display the "Nhập kho" button and rejects the request with “Bạn không có quyền thực hiện thao tác này”.<br>3. The use case ends.<br><br>**Step 4_Lines to receive cannot be loaded**<br>1. If the system cannot find the purchase order or cannot load the data, the dialog displays an error message, for example “Không tìm thấy đơn mua hàng để nhập kho: <mã đơn>”.<br>2. The user closes the dialog and opens it again. Return to step 3.<br><br>**Step 4_Purchase order is not in a status that allows receiving**<br>1. If the purchase order is not "Đã xác nhận" or "Nhận một phần" (GBR-GR-01), the dialog displays “Đơn mua hàng không ở trạng thái cho phép nhập kho” with the current status of the order and does not allow creating a receipt.<br>2. The user closes the dialog. The use case ends.<br><br>**Step 4_Purchase order fully received**<br>1. If all lines are fully received, the dialog displays “Tất cả mặt hàng của đơn này đã được nhận đủ.” and does not allow creating a receipt.<br>2. The user closes the dialog. The use case ends.<br><br>**Step 6_Invalid entered data**<br>1. If the received quantity of a line is not a valid number or is negative, the dialog displays “Số lượng nhận của "<sản phẩm>" không hợp lệ.”<br>2. If the received quantity is greater than the remaining quantity, the dialog displays “Số lượng nhận của "<sản phẩm>" vượt số còn lại (<số lượng>).”<br>3. If all lines are 0, the dialog displays “Phải nhận ít nhất một mặt hàng với số lượng lớn hơn 0.”<br>4. The system does not send the request. The user corrects the data. Return to step 5.<br><br>**Step 7_Purchase order can no longer be received**<br>1. If, while the user was entering data, someone else changed the status of the purchase order or it no longer exists (GBR-GR-01), the system creates no receipt and displays “Không tìm thấy đơn mua hàng để nhập kho: <mã đơn>” or “Đơn mua hàng không ở trạng thái cho phép nhập kho” with the current status.<br>2. The user closes the dialog and reloads the purchase order. Return to step 1.<br><br>**Step 7_Quantity no longer valid against the purchase order**<br>1. If another receipt has just received goods so that the remaining quantity decreased and the quantity now exceeds it (GBR-GR-02), the system creates no receipt and displays “Số lượng nhận vượt quá số còn phải nhận. Nhận: <số lượng>, Còn lại: <số lượng>”.<br>2. If a received line does not belong to the purchase order or is duplicated, the system displays “Dòng nhập không thuộc đơn mua hàng này: <mã dòng>” or “Dòng đơn mua bị lặp lại nhiều lần trong cùng phiếu nhập: <mã dòng>”.<br>3. The user closes the dialog and opens it again to get the new remaining quantities. Return to step 3.<br><br>**Step 7_Request code used with different content**<br>1. If the request code has already been used for a receipt with different content, the system creates no receipt and displays “Mã yêu cầu <mã> đã được dùng cho một phiếu nhập kho với nội dung khác”.<br>2. The user closes the dialog and opens it again to create a new request. Return to step 3.<br><br>**Step 7_Submitted data is invalid**<br>1. If the submitted data lacks required information and the screen did not block it, the system creates no receipt and displays “Dữ liệu đầu vào không hợp lệ”.<br>2. The user corrects the data. Return to step 5. |  |  |
| Postconditions | 1. After step 11 a goods receipt in the "Đã xác nhận" status is saved with the receipt code, purchase order, receipt date, supplier invoice number, note, the creating user and the confirmation time, together with the received lines (SKU, unit, quantity, purchase unit cost, amount) and the receipt total value.<br>2. The on-hand stock of each SKU in the purchase order's warehouse increases by exactly the received quantity, and one stock history entry of the type "Nhập hàng" (goods receipt) referring to the receipt code is recorded.<br>3. The received quantities of the purchase order lines increase; the purchase order is "Nhận một phần" or "Hoàn thành" (Completed).<br>4. A created receipt cannot be edited or cancelled.<br>5. When the action is not successful or is cancelled, no receipt is created, and the stock and the purchase order do not change. |  |  |

## Business Rules
| GBR-ID | Rule Statement | Applies To | Rationale | Enforced By |
| :-: | :-- | :-: | :-- | :-- |
| **GBR-GR-01** | Goods can be received only for a purchase order that exists and is in the "Đã xác nhận" or "Nhận một phần" status. | UC-16.1 (step 2, step 7) | Only receive goods for orders that are approved and not yet completed, cancelled or closed. | Screen (button hidden) and the system (receiving service, purchase order lock and check) |
| **GBR-GR-02** | Only lines that belong to the purchase order can be received; the received quantity of each line cannot exceed the remaining quantity (ordered quantity minus received quantity). | UC-16.1 (step 7) | Avoid receiving more than was ordered from the supplier. | System (receiving service and purchase order service) |
| **GBR-GR-03** | Creating a receipt confirms it immediately: the receipt is "Đã xác nhận" and cannot be edited or cancelled; the receipt code is generated by the system; the receipt date is the creation date; the line amount equals the purchase unit cost on the purchase order times the received quantity and the receipt total equals the sum of the line amounts; the on-hand stock of the SKU in the purchase order's warehouse increases by exactly the received quantity and is recorded in the stock history. | UC-16.1 (step 8, step 9) | Stock changes only with a clear, traceable receiving document that cannot be changed afterwards. | System (receiving, stock and stock history services) |
| **GBR-GR-04** | After a receipt is created, the received quantity of each purchase order line increases by the quantity received. The purchase order becomes "Hoàn thành" when all lines have received the full ordered quantity, otherwise "Nhận một phần". | UC-16.1 (step 10) | The purchase order reflects the real receiving progress so that it is known what is still to be received. | System (purchase order service) |

## Out of Scope (not supported by the current code or covered by another use case)

| Item | Note |
| :-- | :-- |
| Draft receipts, editing or cancelling a created receipt | Creating a receipt confirms it immediately; there is no edit or cancel |
| Attaching a supplier invoice image from the screen | The system has a field for the image link but the screen has no upload field |
| Managing batches, expiry dates and serial numbers when receiving | Not available |
| Receiving goods without a purchase order | Not available; every receipt must be linked to a purchase order |
| Viewing the receipt list and details, creating and approving purchase orders | Separate use cases |
| Updating the cost price of the SKU from the receipt | Not available |
