# UC-17.2 – Configure Safety Threshold

> English version of `UC-17.2-use-case-specification.vi.md` (the Vietnamese version is the source; keep both in sync). Written to match the **current code**. Messages are quoted exactly as they appear on the screen (Vietnamese).

| Primary Actors | Shop Owner | Secondary Actors | None |
| Created By | Pham Van Nam | Created Date | 24/11/2026 |
| Description | As the Shop Owner, I want to set the minimum stock threshold (safety stock) and the maximum stock threshold of each SKU, so that the system marks and warns when stock is running low and has a basis to suggest the purchase quantity when creating a purchase order. The use case changes only the thresholds, not the stock quantities. |  |  |
| Preconditions | 1. The user is logged in with the Shop Owner role.<br>2. The SKU to configure has a stock record and the user is viewing the inventory list (UC-17.1). |  |  |
| Normal Flow | **Configure the safety threshold**<br>1. The user finds the SKU to configure in the inventory list.<br>2. The user chooses "Ngưỡng" (Threshold) on that SKU.<br>3. The system displays the "Cấu hình ngưỡng tồn — <SKU>" dialog showing the product name, the current available stock and two fields: "Ngưỡng tồn tối thiểu (safety stock)" (showing the current value, default 0) and "Ngưỡng tồn tối đa (tùy chọn)" (optional).<br>4. The user enters the minimum threshold and, if wanted, the maximum threshold, then chooses "Lưu ngưỡng" (Save threshold).<br>5. The system validates the entered data (The minimum stock threshold is required and a number greater than or equal to 0; the maximum stock threshold is optional and, if given, a number greater than or equal to 0. Each threshold has at most 2 decimal places and at most 10 integer digits).<br>6. The system checks that the maximum threshold is not smaller than the minimum threshold according to GBR-TH-01, then saves the new thresholds for the SKU; the on-hand quantity and the reserved quantity do not change.<br>7. The system records the change with the responsible user, the old and the new thresholds and, if the SKU is low on stock under the new threshold, records a low-stock alert (GBR-TH-02).<br>8. The system closes the dialog and displays “Đã cập nhật ngưỡng tồn an toàn thành công.” From the next display, the inventory list shows the new threshold and status of the SKU (GBR-TH-03). |  |  |
| Alternative Flows | **Step 4_Leave the maximum threshold empty**<br>1. The user leaves the "Ngưỡng tồn tối đa" field empty.<br>2. The system saves the SKU without a maximum threshold (no limit). Continue at step 5.<br><br>**Step 4_Turn off the low-stock warning**<br>1. The user sets the minimum threshold to 0.<br>2. The system saves the threshold; the SKU is no longer monitored for low stock (GBR-TH-03). Continue at step 5.<br><br>**Step 4_Cancel**<br>1. The user chooses "Hủy" or closes the dialog.<br>2. The system does not save any change. The use case ends. |  |  |
| Exception Flow | **Step 2_No permission**<br>1. If the user is not signed in or the session has expired, the system displays “Chưa xác thực hoặc phiên đăng nhập đã hết hạn”.<br>2. If the user is not the Shop Owner, the system does not display the "Ngưỡng" button; if the request is still sent, the system rejects it with “Bạn không có quyền thực hiện thao tác này”.<br>3. The use case ends.<br><br>**Step 5_Invalid data**<br>1. If the minimum threshold is empty or not a number, the dialog displays “Ngưỡng tối thiểu không hợp lệ”; if it is smaller than 0, it displays “Ngưỡng tối thiểu phải ≥ 0”.<br>2. If the maximum threshold is not a number, the dialog displays “Ngưỡng tối đa không hợp lệ”; if it is smaller than 0, it displays “Ngưỡng tối đa phải ≥ 0”.<br>3. If the maximum threshold is smaller than the minimum threshold, the dialog displays “Ngưỡng tối đa phải ≥ ngưỡng tối thiểu”.<br>4. The system does not send the request. The user corrects the data. Return to step 4.<br><br>**Step 6_Submitted data is invalid**<br>1. If the submitted data has more than 2 decimal places or more than 10 integer digits, the system does not save and displays “Dữ liệu đầu vào không hợp lệ”.<br>2. If the thresholds violate GBR-TH-01 and the screen did not block it, the system does not save and displays “Ngưỡng tồn kho không hợp lệ: tối thiểu phải ≥ 0 và tối đa (nếu có) phải ≥ tối thiểu”.<br>3. The user corrects the data. Return to step 4.<br><br>**Step 6_Stock record of the SKU not found**<br>1. If the SKU no longer has a stock record, the system does not save and displays “Không tìm thấy thông tin tồn kho của sản phẩm: <mã SKU>”.<br>2. The user closes the dialog and reloads the list. Return to step 1.<br><br>**Step 6_Cannot be saved**<br>1. If the system cannot save because of another error, the dialog displays the system's error message or “Không thể cập nhật ngưỡng tồn kho”.<br>2. The thresholds of the SKU do not change. The user tries again. Return to step 4.<br><br>**Step 7_Recording the log or the alert fails**<br>1. The log and the alert are recorded after the new thresholds have been saved successfully. If recording fails, the new thresholds are kept and the failure is written to the system log for follow-up.<br>2. The user still sees the success message of step 8. |  |  |
| Postconditions | 1. After step 8 the SKU has the new minimum threshold and maximum threshold (if any); the on-hand quantity and the reserved quantity do not change.<br>2. A log entry with the responsible user, the time, the old and the new thresholds exists (see "Step 7_Recording the log or the alert fails").<br>3. The "Sắp hết" (Low stock) status of the SKU and the purchase quantity suggestion use the new thresholds.<br>4. When the action is not successful or is cancelled, the thresholds of the SKU do not change. |  |  |

## Business Rules
| GBR-ID | Rule Statement | Applies To | Rationale | Enforced By |
| :-: | :-- | :-: | :-- | :-- |
| **GBR-TH-01** | If a maximum stock threshold is given it must be greater than or equal to the minimum stock threshold. | UC-17.2 (step 5, step 6) | A maximum smaller than the minimum is meaningless and makes the purchase suggestion wrong. | Configuration dialog and the system (inventory service) |
| **GBR-TH-02** | If after the change the SKU is low on stock (minimum threshold greater than 0 and available stock less than or equal to the threshold), the system records a low-stock alert for staff review. The system does not create a purchase order and does not choose a purchase quantity by itself. | UC-17.2 (step 7) | Warn in time when the new threshold puts a SKU at a low level, while the purchasing decision stays with people. | System (inventory service, alert handling) |
| **GBR-TH-03** | The minimum threshold decides the "Sắp hết" status of the SKU (see GBR-IV-02 in UC-17.1); a minimum threshold of 0 means the SKU is not monitored. The maximum threshold is used to suggest the purchase quantity when creating a purchase order. | UC-17.2 (step 8, "Step 4_Turn off the low-stock warning" flow) | Thresholds are inputs for stock monitoring and purchase suggestion. | System (inventory service and purchase order service) |

## Out of Scope (not supported by the current code or covered by another use case)

| Item | Note |
| :-- | :-- |
| Showing the low-stock alert to staff (on-screen notification, e-mail) | Currently the alert is only written to the system log |
| Creating a purchase order or choosing the purchase quantity automatically when stock is low | Not done by the system; staff decide |
| Setting thresholds for several SKUs at once | One SKU is configured at a time |
| Viewing the threshold change history on the screen | The log is stored but there is no screen to view it |
| Looking up the inventory | Covered by UC-17.1 |
