# UC-02.1 – Login

> English version of `UC-02.1-use-case-specification.vi.md` (the Vietnamese version is the source; keep both in sync). Written to match the **current code**. Messages are quoted exactly as they appear on the screen (Vietnamese).

|  |  |  |  |
| :-: | :-- | :-: | :-- |
| Primary Actors | Registered users (Customer, Sales Staff, Accountant, Shipper, Shop Owner) | Secondary Actors | None |
| Created By | Pham Van Nam | Created Date | 24/11/2026 |
| Description | As a registered user, I want to log in with my email and password so that I can use the features available to authenticated users according to my role. |  |  |
| Preconditions | 1. The user has a registered and activated account (the account status is Active). |  |  |
| Normal Flow | **Login**<br>1. The user opens the Login page.<br>2. The system displays the login form with the Email and Password fields.<br>3. The user enters the registered email and password.<br>4. The user submits the login form.<br>5. The system validates the login data (the email is required, in a valid format and at most 320 characters, leading and trailing spaces are removed; the password is required and at most 100 characters).<br>6. The system looks up the account by email and checks the account status according to GBR-AU-01.<br>7. The system authenticates the account (verifies the password) according to GBR-AU-02.<br>8. The system creates a login session for the user according to GBR-AU-03.<br>9. The system redirects the user to the appropriate page based on the user's role. |  |  |
| Alternative Flows | **Step 3_User does not have an account**<br>1. If the user does not have an account, the user selects the "Đăng ký" (Register) link on the login page.<br>2. The system redirects the user to the customer account registration page. The use case ends. |  |  |
| Exception Flow | **Step 5_Invalid login data**<br>1. If the email or password is empty, the email format is wrong, or a value exceeds the allowed length, the system does not send the login request and displays an error under the invalid field, for example “Email không được để trống”, “Email không đúng định dạng”, “Mật khẩu không được để trống”.<br>2. The user enters the data again. Return to step 3.<br><br>**Step 6_Account not active**<br>1. If the account status is Pending activation, Inactive or Locked (GBR-AU-01), the system does not allow the login.<br>2. The system displays “Tài khoản của bạn đã bị vô hiệu hóa hoặc không ở trạng thái hoạt động.”<br>3. The user can log in only after the account is active again. The use case ends.<br><br>**Step 7_Incorrect email or password**<br>1. If no account matches the email, or the password is incorrect (GBR-AU-02), the system does not authenticate the user.<br>2. The system displays “Email hoặc mật khẩu không chính xác.”<br>3. The user can enter the credentials again. Return to step 3.<br><br>**Step 8_Authentication service unavailable**<br>1. If the system cannot access the account data or cannot store the login session, the system does not log the user in.<br>2. The system displays “Dịch vụ xác thực tạm thời không khả dụng. Vui lòng thử lại sau.”<br>3. The user tries again later. Return to step 3. |  |  |
| Postconditions | 1. The user is authenticated and has a new login session with a session duration according to GBR-AU-03.<br>2. When the login is not successful, the system does not create a login session and the account data is not changed. |  |  |

## Business Rules
| GBR-ID | Rule Statement | Applies To | Rationale | Enforced By |
| :-: | :-- | :-: | :-- | :-- |
| **GBR-AU-01** | Only an account with the Active status can log in; an account that is Pending activation, Inactive or Locked is rejected. | UC-02.1 (step 6) | Keep accounts that are not activated or were deactivated by the Shop Owner out of the system. | System (authentication service) |
| **GBR-AU-02** | The system finds the account by email (ignoring letter case) and compares the password with the encrypted password; a non-existent email and a wrong password share one message; login is by email only. | UC-02.1 (step 7) | Protect the stored passwords and do not reveal which emails are registered. | System (authentication service, password encryption) |
| **GBR-AU-03** | Every successful login creates a new session, independent of other sessions; the access token is valid for 30 minutes and the refresh token and session for at most 15 days; the system returns the user information and the active roles. | UC-02.1 (step 8) | Limit the risk of a leaked token while keeping login convenient and allowing use on several devices. | System (authentication service, token issuing, session storage) |

## Out of Scope (not supported by the current code)

| Item | Note |
| :-- | :-- |
| Login with Google, login by phone number | Login by email only |
| "Remember me" | The screen has no such option |
| Automatically locking an account after several wrong passwords | An account is locked only when the Shop Owner sets the status to Locked |
| Login logging (time, IP address, device) | Login events are not logged |
| Logout, session refresh, viewing the current user information, forgot password | These are separate use cases |
