# UC-22.6 – View Warranty Tickets

> English version of `UC-22.6-use-case-specification.vi.md` (the Vietnamese version is the source; keep both in sync). Written to match the **current code**. Messages are quoted exactly as they appear on the screen (Vietnamese).
> The team removed the Technical Staff role (24/11/2026); handling warranty tickets is split into UC-22.6 (view) and UC-22.7 (process).

| Description | As the Shop Owner, I want to view the list and the details of the warranty tickets submitted by customers, so that I know which tickets are waiting and have all the information I need before handling them (UC-22.7). The use case is read-only and changes no data. |  |  |
| Preconditions | 1. The user is logged in with the Shop Owner role.<br>2. Customers have submitted warranty tickets through the online warranty claim function. If no ticket exists yet, the list is empty. |  |  |
| Normal Flow | **View warranty tickets**<br>1. The Shop Owner opens the "Yêu cầu bảo hành" (Warranty Tickets) page.<br>2. The system displays the ticket list, 20 rows per page, most recently submitted first, with the line "Hiển thị <số dòng> / <tổng số> yêu cầu". Each row shows Yêu cầu (code and issue description), Sản phẩm, Địa chỉ, Ngày gửi, Trạng thái (Chờ tiếp nhận, Đang xử lý, Hoàn tất, Bị từ chối, Đã hủy) and the action "Chi tiết".<br>3. The Shop Owner chooses "Chi tiết" on a ticket.<br>4. The system displays the details: the customer's contact information, issue description, preferred date and time slot, service address, attached photos/videos, warranty card information (product, serial number, warranty period), the status and, if already available, the processing result, the rejection reason or the customer's cancellation reason. The use case ends; from here the Shop Owner can handle the ticket in UC-22.7. |  |  |
| Alternative Flows | **Step 2_Filter by status**<br>1. The Shop Owner selects a Status in the filter.<br>2. The system shows only the tickets with that status. Continue at step 3.<br><br>**Step 2_No ticket**<br>1. If there is no ticket or no ticket matches the filter, the system displays “Không có yêu cầu bảo hành phù hợp.”<br>2. The use case ends.<br><br>**Step 4_Warranty card has expired**<br>1. If the expiry date of the card is earlier than the current date (GBR-WP-04), the details additionally show an expiry warning with the expiry date and whether the customer confirmed submitting the ticket anyway.<br>2. The system only warns and does not block viewing. The use case ends.<br><br>**Step 4_Ticket is in a final status**<br>1. For a Hoàn tất, Bị từ chối or Đã hủy ticket (GBR-WP-01), the details show the processing result, the rejection reason or the customer's cancellation reason.<br>2. The ticket can no longer be handled. The use case ends. |  |  |
| Exception Flow | **Step 1_No permission**<br>1. If the user is not signed in or the session has expired, the system displays “Chưa xác thực hoặc phiên đăng nhập đã hết hạn”.<br>2. If the user is not the Shop Owner, the system rejects the request and displays “Bạn không có quyền thực hiện thao tác này”.<br>3. The system does not display any ticket data. The use case ends.<br><br>**Step 4_Ticket not found**<br>1. If the ticket no longer exists, the system displays “Không tìm thấy yêu cầu bảo hành: <mã yêu cầu>”.<br>2. The user closes the details and reloads the list. Return to step 2. |  |  |
| Postconditions | 1. The ticket list or details are displayed; no data is changed.<br>2. When the user has no permission or the ticket is not found, no data is displayed or changed. |  |  |

## Business Rules

| GBR-ID | Rule Statement | Applies To | Rationale | Enforced By |
| :-: | :-- | :-: | :-- | :-- |
| **GBR-WP-01** | A warranty ticket has the statuses: Chờ tiếp nhận (New), Đang xử lý (In progress), Hoàn tất (Done), Bị từ chối (Rejected), Đã hủy (Cancelled). Hoàn tất, Bị từ chối and Đã hủy are final statuses and cannot change further. For the status transition rules see GBR-WP-02 and GBR-WP-03 (UC-22.7). | UC-22.6 (step 2, step 4) | Shows where a ticket is in the process and which tickets still need handling. | System (warranty ticket service) |
| **GBR-WP-04** | A warranty card is considered expired when its expiry date is earlier than the current date. The system only warns; whether to reject or still handle the ticket is the Shop Owner's decision. | UC-22.6 (step 4) | The Shop Owner needs to know the card has expired but may still want to support the customer. | System (warranty ticket service) and the details screen |
