UC-06.3 – Manage Brands

Primary ActorsShop Owner (or a user who has been granted the brand management permissions)Secondary ActorsNone
Created ByPham Van NamCreated Date24/11/2026
DescriptionAs the Shop Owner, I want to view, add, edit, hide or show again, and delete the information of sanitary equipment brands, so that products are linked to the right brand and the brand list is always accurate.
Preconditions1. The user is logged in.
2. The user has the permission that matches the action (view, create, edit or delete brands), granted to the user's role by the Shop Owner (UC-03.5).
Normal FlowAdd a brand
1. The user opens the Brand Management page.
2. The system displays the list of brands, 20 rows per page, sorted by code ascending. Each row shows the brand code, brand name, status and the actions View, Edit and Delete.
3. The user chooses "Thêm thương hiệu" (Add brand).
4. The system displays the "Thêm thương hiệu" form with: brand code, brand name, status (Active or Inactive) and description (optional).
5. The user enters the data and submits the form.
6. The system validates the entered data (Brand data: the code is required, at most 50 characters, only letters A-Z, digits and underscores, the first character a letter or digit (lower case is converted to upper case); the name is required, at most 100 characters; the description is optional, at most 5000 characters (empty means no description); leading and trailing spaces are removed; the status is Active or Inactive (default Active)).
7. The system checks that the brand code and name are not duplicated according to GBR-BD-01 and GBR-BD-02.
8. The system saves the new brand.
9. The system closes the form, refreshes the list and displays “Đã tạo thương hiệu.”
Alternative FlowsStep 2_Search, filter and sort
1. The user types a keyword in the "Tìm theo mã hoặc tên..." field, selects a status (All, Active, Inactive), and selects the sort field and order (ascending, descending).
2. The system displays the matching brands. If no brand matches, the system displays “Không tìm thấy thương hiệu phù hợp.”
3. The user chooses "Đặt lại" (Reset) to clear the filters.

Step 3_View brand details
1. The user chooses "Xem" (View) on a brand.
2. The system displays the read-only "Chi tiết thương hiệu" dialog: code, name, status, description.
3. The user closes the dialog. The use case ends.

Step 3_Edit a brand
1. The user chooses "Sửa" (Edit) on a brand.
2. The system displays the "Sửa thương hiệu" form with the current data; the brand code field cannot be edited (“Mã là khóa ổn định và không thể thay đổi.”) (GBR-BD-01).
3. The user edits the name, description or status and submits the form.
4. The system validates the data according to checks that the name is not duplicated according to GBR-BD-02 and saves the changes.
5. The system closes the form, refreshes the list and displays “Đã cập nhật thương hiệu.” The use case ends.

Step 3_Hide or show a brand again
1. When editing a brand, the user changes the Status to "Ngừng hoạt động" (Inactive) to hide the brand, or to "Hoạt động" (Active) to show it again, and submits the form.
2. The system saves the new status. An Inactive brand is hidden from the selection lists and from the store (GBR-BD-03); it can still be seen in the Brand Management page. The use case ends.

Step 3_Delete a brand
1. The user chooses "Xóa" (Delete) on a brand.
2. The system displays the "Xác nhận xóa thương hiệu" dialog showing the brand code and name.
3. The user chooses "Xóa thương hiệu".
4. The system changes the brand to the Inactive status and keeps its data (GBR-BD-04).
5. The system closes the dialog, refreshes the list (the brand is still shown with the status Ngừng hoạt động) and displays “Đã xóa thương hiệu.” The use case ends.

Step 5_Cancel
1. The user closes the form without submitting.
2. The system does not save any data. The use case ends.

Step 3_Cancel the deletion
1. The user chooses "Hủy" on the delete confirmation dialog.
2. The system closes the dialog and does not change any data. The use case ends.
Exception FlowStep 1_No access
1. If the user is not signed in or the session has expired, the system displays “Chưa xác thực hoặc phiên đăng nhập đã hết hạn”.
2. If the user does not have the permission, the system displays “Tài khoản không có quyền thực hiện thao tác này.”
3. The system does not display or change data. The use case ends.

Step 2_List cannot be loaded
1. If the system cannot load the list, it displays “Chưa thể tải dữ liệu.” with a "Thử lại" (Retry) button.
2. The user chooses "Thử lại". Return to step 2.

Step 6_Invalid data
1. If the data is invalid, the system does not send the data and displays an error next to the invalid field: “Vui lòng nhập mã.”, “Mã tối đa 50 ký tự.”, “Mã chỉ gồm chữ A-Z, số và dấu gạch dưới; ký tự đầu phải là chữ hoặc số.”, “Vui lòng nhập tên.”, “Tên tối đa 100 ký tự.”, “Mô tả tối đa 5000 ký tự.”
2. If the server still rejects a wrongly formatted code, the system displays “Mã thương hiệu không đúng định dạng.”
3. The user corrects the data. Return to step 5 (when editing a brand: return to step 3 of the "Edit a brand" flow).

Step 7_Duplicate code or name
1. If the code already exists (GBR-BD-01), the system does not save and displays “Mã thương hiệu đã tồn tại.”
2. If the name already exists (GBR-BD-02), the system does not save and displays “Tên thương hiệu đã tồn tại.” (both when adding and when editing).
3. The user corrects the data. Return to step 5 (when editing: return to step 3 of the "Edit a brand" flow).

Step 3_Brand no longer exists
1. If the brand to edit or delete no longer exists, the system changes no data and displays “Không tìm thấy thương hiệu yêu cầu”.
2. The user closes the dialog and reloads the list. Return to step 1.
Postconditions1. After step 9 a new brand is saved with the entered code (upper case), name, description and status, and it appears in the list.
2. After the "Edit a brand" flow (including hide or show again) the name, description and status are updated; the brand code does not change.
3. After the "Delete a brand" flow the brand is Inactive and is still in the data.
4. When the action is not successful or is cancelled, the brand data does not change. Viewing, searching and viewing details do not change any data.

Business Rules

GBR-BD-01The brand code is unique in the whole system (ignoring letter case) and cannot be changed after creation.UC-06.3 (step 7, step 2 of the "Edit a brand" flow)The code is a stable key that other functions (products, warranty policies, Excel import) use to refer to a brand.System (brand service) and database (unique key)
GBR-BD-02The brand name is unique in the whole system (ignoring letter case and leading or trailing spaces).UC-06.3 (step 7, step 4 of the "Edit a brand" flow)Avoid two identical brands that cause confusion when choosing a brand for a product.System (brand service)
GBR-BD-03A brand with the Inactive status is hidden from the brand selection lists, from the Excel product import and from the brand list shown to customers in the store; it can still be seen in the Brand Management page.UC-06.3 (step 2 of the "Hide or show a brand again" flow)Allow a brand to stop being used without losing data and without affecting customers.System (the brand, store and Excel import services use active brands only)
GBR-BD-04Deleting a brand is a soft delete: the brand changes to the Inactive status and its data is kept. The system does not check whether products use the brand. Deleting a brand that is already Inactive causes no error and changes nothing.UC-06.3 (step 4 of the "Delete a brand" flow)Keep the history and the references of products and warranty policies that already use the brand.System (brand service)
