UC-17.2 – Configure Safety Threshold

Primary ActorsShop OwnerSecondary ActorsNone
Created ByPham Van NamCreated Date24/11/2026
DescriptionAs the Shop Owner, I want to set the minimum stock threshold (safety stock) and the maximum stock threshold of each SKU, so that the system marks and warns when stock is running low and has a basis to suggest the purchase quantity when creating a purchase order. The use case changes only the thresholds, not the stock quantities.
Preconditions1. The user is logged in with the Shop Owner role.
2. The SKU to configure has a stock record and the user is viewing the inventory list (UC-17.1).
Normal FlowConfigure the safety threshold
1. The user finds the SKU to configure in the inventory list.
2. The user chooses "Ngưỡng" (Threshold) on that SKU.
3. The system displays the "Cấu hình ngưỡng tồn — <SKU>" dialog showing the product name, the current available stock and two fields: "Ngưỡng tồn tối thiểu (safety stock)" (showing the current value, default 0) and "Ngưỡng tồn tối đa (tùy chọn)" (optional).
4. The user enters the minimum threshold and, if wanted, the maximum threshold, then chooses "Lưu ngưỡng" (Save threshold).
5. The system validates the entered data (The minimum stock threshold is required and a number greater than or equal to 0; the maximum stock threshold is optional and, if given, a number greater than or equal to 0. Each threshold has at most 2 decimal places and at most 10 integer digits).
6. The system checks that the maximum threshold is not smaller than the minimum threshold according to GBR-TH-01, then saves the new thresholds for the SKU; the on-hand quantity and the reserved quantity do not change.
7. The system records the change with the responsible user, the old and the new thresholds and, if the SKU is low on stock under the new threshold, records a low-stock alert (GBR-TH-02).
8. The system closes the dialog and displays “Đã cập nhật ngưỡng tồn an toàn thành công.” From the next display, the inventory list shows the new threshold and status of the SKU (GBR-TH-03).
Alternative FlowsStep 4_Leave the maximum threshold empty
1. The user leaves the "Ngưỡng tồn tối đa" field empty.
2. The system saves the SKU without a maximum threshold (no limit). Continue at step 5.

Step 4_Turn off the low-stock warning
1. The user sets the minimum threshold to 0.
2. The system saves the threshold; the SKU is no longer monitored for low stock (GBR-TH-03). Continue at step 5.

Step 4_Cancel
1. The user chooses "Hủy" or closes the dialog.
2. The system does not save any change. The use case ends.
Exception FlowStep 2_No permission
1. If the user is not signed in or the session has expired, the system displays “Chưa xác thực hoặc phiên đăng nhập đã hết hạn”.
2. If the user is not the Shop Owner, the system does not display the "Ngưỡng" button; if the request is still sent, the system rejects it with “Bạn không có quyền thực hiện thao tác này”.
3. The use case ends.

Step 5_Invalid data
1. If the minimum threshold is empty or not a number, the dialog displays “Ngưỡng tối thiểu không hợp lệ”; if it is smaller than 0, it displays “Ngưỡng tối thiểu phải ≥ 0”.
2. If the maximum threshold is not a number, the dialog displays “Ngưỡng tối đa không hợp lệ”; if it is smaller than 0, it displays “Ngưỡng tối đa phải ≥ 0”.
3. If the maximum threshold is smaller than the minimum threshold, the dialog displays “Ngưỡng tối đa phải ≥ ngưỡng tối thiểu”.
4. The system does not send the request. The user corrects the data. Return to step 4.

Step 6_Submitted data is invalid
1. If the submitted data has more than 2 decimal places or more than 10 integer digits, the system does not save and displays “Dữ liệu đầu vào không hợp lệ”.
2. If the thresholds violate GBR-TH-01 and the screen did not block it, the system does not save and displays “Ngưỡng tồn kho không hợp lệ: tối thiểu phải ≥ 0 và tối đa (nếu có) phải ≥ tối thiểu”.
3. The user corrects the data. Return to step 4.

Step 6_Stock record of the SKU not found
1. If the SKU no longer has a stock record, the system does not save and displays “Không tìm thấy thông tin tồn kho của sản phẩm: <mã SKU>”.
2. The user closes the dialog and reloads the list. Return to step 1.

Step 6_Cannot be saved
1. If the system cannot save because of another error, the dialog displays the system's error message or “Không thể cập nhật ngưỡng tồn kho”.
2. The thresholds of the SKU do not change. The user tries again. Return to step 4.

Step 7_Recording the log or the alert fails
1. The log and the alert are recorded after the new thresholds have been saved successfully. If recording fails, the new thresholds are kept and the failure is written to the system log for follow-up.
2. The user still sees the success message of step 8.
Postconditions1. After step 8 the SKU has the new minimum threshold and maximum threshold (if any); the on-hand quantity and the reserved quantity do not change.
2. A log entry with the responsible user, the time, the old and the new thresholds exists (see "Step 7_Recording the log or the alert fails").
3. The "Sắp hết" (Low stock) status of the SKU and the purchase quantity suggestion use the new thresholds.
4. When the action is not successful or is cancelled, the thresholds of the SKU do not change.

Business Rules

GBR-TH-01If a maximum stock threshold is given it must be greater than or equal to the minimum stock threshold.UC-17.2 (step 5, step 6)A maximum smaller than the minimum is meaningless and makes the purchase suggestion wrong.Configuration dialog and the system (inventory service)
GBR-TH-02If after the change the SKU is low on stock (minimum threshold greater than 0 and available stock less than or equal to the threshold), the system records a low-stock alert for staff review. The system does not create a purchase order and does not choose a purchase quantity by itself.UC-17.2 (step 7)Warn in time when the new threshold puts a SKU at a low level, while the purchasing decision stays with people.System (inventory service, alert handling)
GBR-TH-03The minimum threshold decides the "Sắp hết" status of the SKU (see GBR-IV-02 in UC-17.1); a minimum threshold of 0 means the SKU is not monitored. The maximum threshold is used to suggest the purchase quantity when creating a purchase order.UC-17.2 (step 8, "Step 4_Turn off the low-stock warning" flow)Thresholds are inputs for stock monitoring and purchase suggestion.System (inventory service and purchase order service)
