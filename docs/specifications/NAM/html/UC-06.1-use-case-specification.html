UC-06.1 – Manage Category Hierarchy

Primary ActorsShop Owner (or a user who has been granted the category management permissions)Secondary ActorsNone
Created ByPham Van NamCreated Date24/11/2026
DescriptionAs the Shop Owner, I want to view the product categories and their parent-child relationships and add a new category (a root category or a child of another category), so that products are classified in a structured way.
Preconditions1. The user is logged in.
2. The user has the permission to view categories (and the permission to create categories when adding one), granted to the user's role by the Shop Owner (UC-03.5).
Normal FlowAdd a category
1. The user opens the Category Management page.
2. The system displays a flat list of categories, 20 rows per page, sorted by code ascending. Each row shows the category code, name, parent category ("Danh mục gốc" when there is no parent), status, last update and the actions View, Edit and Delete.
3. The user chooses "Thêm danh mục" (Add category).
4. The system displays the "Thêm danh mục" form with: category code, category name, parent category (default "Danh mục gốc", listing only active categories), status (Active or Inactive) and description.
5. The user enters the data, selects a parent category to create a child category, and submits the form.
6. The system validates the entered data (Category data: the code is required, at most 50 characters, only letters A-Z, digits and underscores, the first character a letter or digit (lower case is converted to upper case); the name is required, at most 100 characters; the description is at most 5000 characters (empty means no description); leading and trailing spaces are removed; the status is Active or Inactive (default Active)).
7. The system checks that the category code and name are not duplicated according to GBR-CG-01 and GBR-CG-02.
8. The system checks the parent category according to GBR-CG-03.
9. The system saves the new category.
10. The system closes the form, refreshes the list and displays “Đã tạo danh mục.”
Alternative FlowsStep 2_Search, filter and sort
1. The user types a keyword in the "Tìm theo mã hoặc tên..." field, selects a status (All, Active, Inactive), and selects the sort field and order (ascending, descending).
2. The system displays the matching categories. If no category matches, the system displays “Không tìm thấy danh mục phù hợp.”
3. The user chooses "Đặt lại" (Reset) to clear the filters.

Step 3_View category details
1. The user chooses "Xem" (View) on a category.
2. The system displays the read-only "Chi tiết danh mục" dialog: code, name, parent category, status, description.
3. The user closes the dialog. The use case ends.

Step 5_Create a root category
1. The user keeps "Danh mục gốc" in the Parent category field.
2. The system creates the category without a parent. Continue at step 6.

Step 5_Cancel
1. The user closes the form without submitting.
2. The system does not save any data. The use case ends.
Exception FlowStep 1_No access
1. If the user is not signed in or the session has expired, the system displays “Chưa xác thực hoặc phiên đăng nhập đã hết hạn”.
2. If the user does not have the permission, the system displays “Tài khoản không có quyền thực hiện thao tác này.”
3. The system does not display or save data. The use case ends.

Step 2_List cannot be loaded
1. If the system cannot load the list, it displays “Chưa thể tải dữ liệu.” with a "Thử lại" (Retry) button.
2. The user chooses "Thử lại". Return to step 2.

Step 6_Invalid data
1. If the data is invalid, the system does not send the data and displays an error next to the invalid field: “Vui lòng nhập mã.”, “Mã tối đa 50 ký tự.”, “Mã chỉ gồm chữ A-Z, số và dấu gạch dưới; ký tự đầu phải là chữ hoặc số.”, “Vui lòng nhập tên.”, “Tên tối đa 100 ký tự.”, “Mô tả tối đa 5000 ký tự.”
2. If the server still rejects a wrongly formatted code, the system displays “Mã danh mục không đúng định dạng.”
3. The user corrects the data. Return to step 5.

Step 7_Duplicate code or name
1. If the code already exists (GBR-CG-01), the system does not save and displays “Mã danh mục đã tồn tại.”
2. If the name already exists under the same parent category (GBR-CG-02), the system does not save and displays “Tên danh mục đã tồn tại trong cùng danh mục cha.”
3. The user corrects the data. Return to step 5.

Step 8_Invalid parent category
1. If the selected parent category no longer exists (for example someone else just deleted it), the system does not save and displays “Danh mục cha không còn tồn tại.”
2. If the category structure is in conflict, the system does not save and displays “Cấu trúc danh mục đang xung đột. Vui lòng tải lại và thử lại.”
3. The user selects the parent category again. Return to step 5.
Postconditions1. After step 10 a new category is saved with the code (upper case), name, description, status and the selected parent category (or as a root category), and it appears in the list.
2. When the action is not successful or is cancelled, no category is created.
3. Viewing, searching and viewing details do not change any data.

Business Rules

GBR-CG-01The category code is unique in the whole system (ignoring letter case) and cannot be changed after creation.UC-06.1 (step 7), UC-06.2 (step 2)The code is a stable key that other functions (products, Excel import) use to refer to a category.System (category service) and database (unique key)
GBR-CG-02A category name is unique under the same parent category; root categories cannot have the same name.UC-06.1 (step 7), UC-06.2 (step 5)Avoid confusion when choosing among categories on the same level.System (category service)
GBR-CG-03A category has at most one parent category, or is a root category. The parent category must exist; a category cannot be its own parent and cannot take its own child or descendant as its parent (no loops). The system does not limit the number of levels.UC-06.1 (step 8), UC-06.2 (step 5)Keep the tree valid and prevent loops that would break walking through the category tree.System (category service) and database (parent foreign key)
GBR-CG-04A category with the Inactive status is hidden from the category selection lists (choosing a parent category, choosing a category for a product), from the Excel product import and from the category list shown to customers in the store; it can still be seen in the Category Management page.UC-06.1 (step 4), UC-06.2 (step 4)Allow a category to stop being used without losing data and without affecting customers.System (the category, store and Excel import services only use active categories)
