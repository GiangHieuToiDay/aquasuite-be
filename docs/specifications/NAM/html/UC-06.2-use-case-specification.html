UC-06.2 – Update/Delete Category

Primary ActorsShop Owner (or a user who has been granted the category management permissions)Secondary ActorsNone
Created ByPham Van NamCreated Date24/11/2026
DescriptionAs the Shop Owner, I want to edit the information, change the parent category, hide or show again, and delete a category, so that the product category structure always matches the real business.
Preconditions1. The user is logged in.
2. The user has the permission to edit categories (and the permission to delete categories when deleting), granted to the user's role by the Shop Owner (UC-03.5).
3. The category to edit or delete exists and the user is viewing the category list (UC-06.1).
Normal FlowUpdate a category
1. The user chooses "Sửa" (Edit) on a category in the list.
2. The system displays the "Sửa danh mục" form with the current data. The category code field cannot be edited (“Mã là khóa ổn định và không thể thay đổi.”) and the Parent category list does not contain the category being edited.
3. The user edits the name, description, parent category or status (Active, Inactive) and submits the form.
4. The system validates the entered data (Category data: the code is required, at most 50 characters, only letters A-Z, digits and underscores, the first character a letter or digit (lower case is converted to upper case); the name is required, at most 100 characters; the description is at most 5000 characters (empty means no description); leading and trailing spaces are removed; the status is Active or Inactive (default Active)).
5. The system checks that the name is not duplicated under the same parent according to GBR-CG-02 and checks the parent category according to GBR-CG-03.
6. The system saves the changes.
7. The system closes the form, refreshes the list and displays “Đã cập nhật danh mục.”
Alternative FlowsStep 3_Hide or show a category again
1. The user changes the Status to "Ngừng hoạt động" (Inactive) to hide the category, or to "Hoạt động" (Active) to show it again, and submits the form.
2. The system saves the new status. An Inactive category is hidden from the selection lists and from the store (GBR-CG-04); the status of its child categories is not changed (GBR-CG-06). Continue at step 7.

Step 3_Change the parent category
1. The user selects another parent category, or selects "Danh mục gốc" to move the category to the root level, and submits the form.
2. The system checks according to GBR-CG-03 and saves. All child categories of the category move together with it. Continue at step 4.

Step 3_Cancel
1. The user closes the form without submitting.
2. The system does not save any change. The use case ends.

Step 1_Delete a category
1. The user chooses "Xóa" (Delete) on a category.
2. The system displays the "Xác nhận xóa danh mục" dialog showing the category code and name.
3. The user chooses "Xóa danh mục".
4. The system checks that the category has no child category (GBR-CG-05), changes the category to the Inactive status and keeps its data.
5. The system closes the dialog, refreshes the list (the category is still shown with the status Ngừng hoạt động) and displays “Đã xóa danh mục.” The use case ends.

Step 3_Cancel the deletion
1. The user chooses "Hủy" on the delete confirmation dialog.
2. The system closes the dialog and does not change any data. The use case ends.
Exception FlowStep 1_No access
1. If the user is not signed in or the session has expired, the system displays “Chưa xác thực hoặc phiên đăng nhập đã hết hạn”.
2. If the user does not have the permission, the system displays “Tài khoản không có quyền thực hiện thao tác này.”
3. The system does not change any data. The use case ends.

Step 4_Invalid data
1. If the data is invalid, the system does not send the data and displays an error next to the invalid field: “Vui lòng nhập tên.”, “Tên tối đa 100 ký tự.”, “Mô tả tối đa 5000 ký tự.”
2. The user corrects the data. Return to step 3.

Step 5_Duplicate name
1. If the name already exists under the same parent category (GBR-CG-02), the system does not save and displays “Tên danh mục đã tồn tại trong cùng danh mục cha.”
2. The user corrects the data. Return to step 3.

Step 5_Invalid parent category
1. If the selected parent is the category being edited, the system does not save and displays “Danh mục không thể là cha của chính nó.”
2. If the selected parent is a child or descendant of the category being edited, the system does not save and displays “Không thể chọn danh mục con làm cha vì sẽ tạo vòng lặp.”
3. If the parent category no longer exists, the system does not save and displays “Danh mục cha không còn tồn tại.”
4. If the category structure is in conflict, the system does not save and displays “Cấu trúc danh mục đang xung đột. Vui lòng tải lại và thử lại.”
5. The user selects the parent category again. Return to step 3.

Step 3_Category no longer exists
1. If the category to edit or delete no longer exists, the system changes no data and displays “Không tìm thấy danh mục yêu cầu”.
2. The user closes the dialog and reloads the list. Return to step 1.

Step 4_Category with child categories cannot be deleted
1. If the category has child categories, including inactive ones (GBR-CG-05), the system does not delete it and displays in the confirmation dialog “Không thể xóa danh mục đang có danh mục con.”
2. The user closes the dialog, or handles the child categories and deletes again. The use case ends.
Postconditions1. After step 7 the name, description, parent category and status of the category are updated; the category code does not change.
2. After the "Delete a category" flow the category is Inactive and is still in the data; because a category can be deleted only when it has no child category, the tree structure is not broken.
3. When the action is not successful or is cancelled, the category data does not change.

Business Rules

GBR-CG-01The category code is unique in the whole system (ignoring letter case) and cannot be changed after creation.UC-06.1 (step 7), UC-06.2 (step 2)The code is a stable key that other functions (products, Excel import) use to refer to a category.System (category service) and database (unique key)
GBR-CG-02A category name is unique under the same parent category; root categories cannot have the same name.UC-06.1 (step 7), UC-06.2 (step 5)Avoid confusion when choosing among categories on the same level.System (category service)
GBR-CG-03A category has at most one parent category, or is a root category. The parent category must exist; a category cannot be its own parent and cannot take its own child or descendant as its parent (no loops). The system does not limit the number of levels.UC-06.1 (step 8), UC-06.2 (step 5)Keep the tree valid and prevent loops that would break walking through the category tree.System (category service) and database (parent foreign key)
GBR-CG-04A category with the Inactive status is hidden from the category selection lists (choosing a parent category, choosing a category for a product), from the Excel product import and from the category list shown to customers in the store; it can still be seen in the Category Management page.UC-06.1 (step 4), UC-06.2 (step 3)Allow a category to stop being used without losing data and without affecting customers.System (the category, store and Excel import services only use active categories)
GBR-CG-05Deleting a category is a soft delete: the category changes to the Inactive status and its data is kept. A category that has child categories (even inactive ones) cannot be deleted. Deleting a category that is already Inactive causes no error and changes nothing.UC-06.2 (step 4 of the "Delete a category" flow)Keep the history and the product references, and do not orphan child categories.System (category service)
GBR-CG-06Changing a category to the Inactive status does not change the status of its child categories.UC-06.2 (step 3_Hide or show a category again)Allow hiding each category separately; the user decides whether to hide the whole branch.System (category service)
