UC-22.6 – View Warranty Tickets

Primary ActorsShop OwnerSecondary ActorsNone
Created ByPham Van NamCreated Date24/11/2026
DescriptionAs the Shop Owner, I want to view the list and the details of the warranty tickets submitted by customers, so that I know which tickets are waiting and have all the information I need before handling them (UC-22.7). The use case is read-only and changes no data.
Preconditions1. The user is logged in with the Shop Owner role.
2. Customers have submitted warranty tickets through the online warranty claim function. If no ticket exists yet, the list is empty.
Normal FlowView warranty tickets
1. The Shop Owner opens the "Yêu cầu bảo hành" (Warranty Tickets) page.
2. The system displays the ticket list, 20 rows per page, most recently submitted first, with the line "Hiển thị <số dòng> / <tổng số> yêu cầu". Each row shows Yêu cầu (code and issue description), Sản phẩm, Địa chỉ, Ngày gửi, Trạng thái (Chờ tiếp nhận, Đang xử lý, Hoàn tất, Bị từ chối, Đã hủy) and the action "Chi tiết".
3. The Shop Owner chooses "Chi tiết" on a ticket.
4. The system displays the details: the customer's contact information, issue description, preferred date and time slot, service address, attached photos/videos, warranty card information (product, serial number, warranty period), the status and, if already available, the processing result, the rejection reason or the customer's cancellation reason. The use case ends; from here the Shop Owner can handle the ticket in UC-22.7.
Alternative FlowsStep 2_Filter by status
1. The Shop Owner selects a Status in the filter.
2. The system shows only the tickets with that status. Continue at step 3.

Step 2_No ticket
1. If there is no ticket or no ticket matches the filter, the system displays “Không có yêu cầu bảo hành phù hợp.”
2. The use case ends.

Step 4_Warranty card has expired
1. If the expiry date of the card is earlier than the current date (GBR-WP-04), the details additionally show an expiry warning with the expiry date and whether the customer confirmed submitting the ticket anyway.
2. The system only warns and does not block viewing. The use case ends.

Step 4_Ticket is in a final status
1. For a Hoàn tất, Bị từ chối or Đã hủy ticket (GBR-WP-01), the details show the processing result, the rejection reason or the customer's cancellation reason.
2. The ticket can no longer be handled. The use case ends.
Exception FlowStep 1_No permission
1. If the user is not signed in or the session has expired, the system displays “Chưa xác thực hoặc phiên đăng nhập đã hết hạn”.
2. If the user is not the Shop Owner, the system rejects the request and displays “Bạn không có quyền thực hiện thao tác này”.
3. The system does not display any ticket data. The use case ends.

Step 4_Ticket not found
1. If the ticket no longer exists, the system displays “Không tìm thấy yêu cầu bảo hành: <mã yêu cầu>”.
2. The user closes the details and reloads the list. Return to step 2.
Postconditions1. The ticket list or details are displayed; no data is changed.
2. When the user has no permission or the ticket is not found, no data is displayed or changed.

Business Rules

Hoàn tất, Bị từ chối and Đã hủy are final statuses and cannot change further.
