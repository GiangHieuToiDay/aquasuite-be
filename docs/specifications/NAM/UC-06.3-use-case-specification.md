# UC-06.3 – Manage Brands

> English version of `UC-06.3-use-case-specification.vi.md` (the Vietnamese version is the source; keep both in sync). Written to match the **current code**. Messages are quoted exactly as they appear on the screen (Vietnamese).
> A brand currently has only a **code, name, description and status**. "Delete brand" is a **soft delete**: the brand changes to the Inactive status (hidden) and its data is kept.

|  |  |  |  |
| :-: | :-- | :-: | :-- |
| Primary Actors | Shop Owner (or a user who has been granted the brand management permissions) | Secondary Actors | None |
| Created By | Pham Van Nam | Created Date | 24/11/2026 |
| Description | As the Shop Owner, I want to view, add, edit, hide or show again, and delete the information of sanitary equipment brands, so that products are linked to the right brand and the brand list is always accurate. |  |  |
| Preconditions | 1. The user is logged in.<br>2. The user has the permission that matches the action (view, create, edit or delete brands), granted to the user's role by the Shop Owner (UC-03.5). |  |  |
| Normal Flow | **Add a brand**<br>1. The user opens the Brand Management page.<br>2. The system displays the list of brands, 20 rows per page, sorted by code ascending. Each row shows the brand code, brand name, status and the actions View, Edit and Delete.<br>3. The user chooses "Thêm thương hiệu" (Add brand).<br>4. The system displays the "Thêm thương hiệu" form with: brand code, brand name, status (Active or Inactive) and description (optional).<br>5. The user enters the data and submits the form.<br>6. The system checks that the brand code and name are not duplicated according to GBR-BD-01 and GBR-BD-02.<br>8. The system saves the new brand.<br>9. The system closes the form, refreshes the list and displays “Đã tạo thương hiệu.” |  |  |

The user types a keyword in the "Tìm theo mã hoặc tên..." field, selects a status (All, Active, Inactive), and selects the sort field and order (ascending, descending).<br>2. The system displays the matching brands. If no brand matches, the system displays “Không tìm thấy thương hiệu phù hợp.”<br>3. The user chooses "Đặt lại" (Reset) to clear the filters.<br><br>**Step 3_View brand details**<br>1. The user chooses "Xem" (View) on a brand.<br>2. The user closes the form without submitting.<br>2. The system does not save any data. The use case ends.<br><br>**Step 3_Cancel the deletion**<br>1. The user chooses "Hủy" on the delete confirmation dialog.<br>2. The system closes the dialog and does not change any data. The use case ends. |  |  |

## Business Rules
| GBR-ID | Rule Statement | Applies To | Rationale | Enforced By |
| :-: | :-- | :-: | :-- | :-- |
| **GBR-BD-01** | The brand code is unique in the whole system (ignoring letter case) and cannot be changed after creation. | UC-06.3 (step 7, step 2 of the "Edit a brand" flow) | The code is a stable key that other functions (products, warranty policies, Excel import) use to refer to a brand. | System (brand service) and database (unique key) |
| **GBR-BD-02** | The brand name is unique in the whole system (ignoring letter case and leading or trailing spaces). | UC-06.3 (step 7, step 4 of the "Edit a brand" flow) | Avoid two identical brands that cause confusion when choosing a brand for a product. | System (brand service) |
| **GBR-BD-03** | A brand with the Inactive status is hidden from the brand selection lists, from the Excel product import and from the brand list shown to customers in the store; it can still be seen in the Brand Management page. | UC-06.3 (step 2 of the "Hide or show a brand again" flow) | Allow a brand to stop being used without losing data and without affecting customers. | System (the brand, store and Excel import services use active brands only) |
| **GBR-BD-04** | Deleting a brand is a soft delete: the brand changes to the Inactive status and its data is kept. The system does not check whether products use the brand. Deleting a brand that is already Inactive causes no error and changes nothing. | UC-06.3 (step 4 of the "Delete a brand" flow) | Keep the history and the references of products and warranty policies that already use the brand. | System (brand service) |

## Out of Scope (not supported by the current code or covered by another use case)

| Item | Note |
| :-- | :-- |
| Other brand information (logo, origin, website...) | A brand currently has only a code, name, description and status |
| Importing brands from Excel | There is an "Nhập Excel" button but it belongs to a separate data import use case |
| Permanently deleting a brand from the database | "Delete" always changes the brand to Inactive |
| Blocking deletion or hiding of a brand that has products | The system does not check products on a soft delete |
| Logging brand changes (who, when, old and new values) | Not logged yet |
